# Ring of Fire

A 3D PC boxing game built with **Three.js + TypeScript + Vite**, presented like a
televised fight night: broadcast HUD, ring walks, commentary ticker, and
over-the-shoulder camera work.

![fight](shots/06-exchange.png)

## Running it

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # production bundle into dist/
npm run typecheck  # tsc --noEmit
```

## The fighters

The boxers are real downloaded human meshes rather than procedurally generated
geometry, because the whole point of the look was *Fight Night Champion*, not
low-poly shapes.

- Body, face, hair, tattoos: **Mixamo "Brute"**, from the
  [`Linzhan/Mixamo-Animations-Characters`](https://huggingface.co/datasets/Linzhan/Mixamo-Animations-Characters)
  mirror, stored at `assets/raw/Brute.glb` (18.5 MB, unmodified).
- Trunks, boots and gloves are generated by the game
  (`src/render/FighterModel.ts`) and fitted to the model's measured bind-pose
  silhouette, so they never intersect the body they sit on.
- The model's own trousers are re-materialled into bare legs — they are the only
  leg geometry in the asset, and being skinned they bend properly at the knee.
- The model's axe, and its knee-high pointed boots, are dropped at load.

### How the retarget works

`src/render/BoxerBody.ts` loads the GLB once and then, per fighter, clones it
with `SkeletonUtils`, rebases every bone onto the game's own joint layout, and
installs a `setJoint` hook. At runtime `Animator.apply()` writes each pose Euler
to both the game rig (which carries the procedural gear and the hitboxes) and —
through that hook — to the Mixamo skeleton:

```
q_bone  = R_parent⁻¹ · pose · R_self        // R = K · B, a per-bone rest frame
pos     = R_parent⁻¹ · (layout - rest_parent) / scale_parent
```

`K` is the constant rotation that folds the model's T-pose arms down to the
game's arms-at-the-sides rest pose (`setFromUnitVectors` from the bind bone axis
to the rest bone axis); it is identity for the spine and legs and a 90° roll for
the arms. Bones the game does not own (`Spine1`, fingers, toes) keep their bind
transform and pass through, so nothing is distorted and the sole lands exactly
on `y = 0`.

## Layout

```
src/core/        game loop, constants, poses, camera, input, audio
src/entities/    Fighter, punch resolution, AI
src/render/      arena, ring, effects, model loading, gear construction
src/ui/          broadcast HUD, menus, commentary ticker
src/data/        fighter roster
assets/raw/      the downloaded source model
scripts/         Playwright capture and model-inspection tools
```

## Dev tooling

Headless screenshots are driven by Playwright with SwiftShader, which renders at
roughly 2 fps — the harnesses stub `Game.render` and step the simulation at a
fixed 60 Hz instead, then restore it for a single frame per capture.

```bash
node scripts/shot.mjs      # full-match gallery -> shots/01..14-*.png
node scripts/diag.mjs      # per-frame state/balance log (PASSIVE=1, FASTROUNDS=1)
node scripts/model.mjs     # close-up fighter viewer -> shots/model/*.png
node scripts/walk.mjs      # step-cycle profile -> shots/walk/*.png
node scripts/hands.mjs     # rig-vs-skeleton joint alignment report
node scripts/glb.mjs assets/raw/Brute.glb         # GLB inventory
node scripts/glbslice.mjs assets/raw/Brute.glb Bottoms   # per-slab silhouette
node scripts/bodydiag.mjs  # joint world positions and fighter bounds
```

The dev server must be running for the Playwright harnesses.
